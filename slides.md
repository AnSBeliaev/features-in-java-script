# Что такое TC39?

**TC39 (Technical Committee 39) — это комитет экспертов,** который разрабатывает и поддерживает стандарт языка программирования JavaScript (ECMAScript).

- Технический комитет при организации Ecma International
- Отвечает за спецификацию языка — ECMAScript
- Состоит из делегатов компаний-производителей браузеров (Google, Mozilla, Apple, Microsoft) и крупных игроков экосистемы
- Решения принимаются **консенсусом**, а не голосованием
- Вся работа — публична и ведётся на GitHub

# Кто такие Champions?

**Champion (или группа champions) — это «чемпион» идеи, член TC39,** который берёт на себя ответственность за продвижение новой фичи с нуля и до самого стандарта.

- **Вдохновитель и автор:** Champion разрабатывает дизайн предложения, пишет черновик спецификации и готовит презентации для комитета.

- **Главный двигатель процесса:** Он представляет фичу на встречах TC39, собирает обратную связь, дорабатывает proposal и ведёт его по всем стадиям — от Stage 0 до Stage 4.

- **Эксперт и «лицо» предложения:** Благодаря глубокому знанию предметной области, champion помогает другим членам комитета и разработчикам со всего мира разобраться в фиче, отвечает на вопросы и участвует в обсуждениях.

- **Не всегда одиночка:** Часто над фичей работает **группа champions** (обычно 1–2 человека из комитета), чтобы распределить нагрузку и учесть разные мнения.

### Почему это важно?

Именно champion гарантирует, что идея не исчезнет, а будет тщательно проработана и доведена до конца. Без чемпиона у фичи нет будущего в языке.

# Декораторы

<div class="grid grid-cols-[1fr_14rem] gap-6 items-start">
<div>

Декоратор — это функция **снаружи** класса или метода. Пишется как `@Injectable()`, `@Get()`, `@logged`.

Angular и Nest так пишут каждый день. TypeScript это понимает, **обычный JS — нет.**

Эту фичу обсуждают с **2016** года. В 2022 казалось, что она почти готова перейти в стадию 3. В **2026** комитет вернул её на 2.7.

Почему так вышло. В обычном файле `.js` в Chrome и Firefox `@logged` просто не работает. У движков не было общего способа проверить, что они делают одно и то же. Плюс в момент создания класса приходится запускать чужой код: подменять методы, трогать приватные поля. Движку проще ускорять класс, когда его устройство заранее известно. Поэтому декораторы так и остались на стороне TypeScript при сборке.

# Почему две функции — это проблема

Вы пишете только `@logged` над методом. Сами `logged()` нигде не вызываете.

TypeScript при сборке превращает `@logged` в обычный вызов. Какие аргументы туда подставить — решает он. В двух режимах это **разные аргументы**.

<div class="grid grid-cols-2 gap-4">

```ts
// Nest / Angular сейчас
function logged(target, key, descriptor) {
  descriptor.value // здесь лежит исходный save
}
```

```ts
// будущий стандарт
function logged(fn, context) {
  fn // исходный save сразу здесь
}
```

</div>

Предположим, вы включили новый режим, а функции остались прежние: они берут `descriptor.value`, а `descriptor` — `undefined`.

`@Injectable` / `@Get` правят Nest и Angular. Свои декораторы придется переписать.
